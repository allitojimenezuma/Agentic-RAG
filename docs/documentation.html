Agentic RAG — The Agent Layer

Four LangChain agents — ingest, query, lint, fix — built with create_agent() + middleware. They share one injected schema (AGENTS.md), one deterministic wiki engine beneath them, and a set of scoped tools per agent: read-only navigation for query, structured extraction for ingest, and human-in-the-loop approval for anything destructive.

Executive Summary / Key Highlights

The Wiki Engine → View GitHub Repository ↗ Live Demo (Streamlit UI) ↗
  • Scope-per-agent security. No god-agent: query gets exactly three read-only tools, fix has no shell and can only act through wiki tools, and every write is filtered by a path-guard middleware that blocks raw/, absolute paths, and ...
  • Zero-hallucination grounding gate. The query agent has no finalization tool — its answer is auto-built from the model's own message, extracting [[Page]] links as citations and dropping any whose slug was never navigated this turn ("cite-or-die").
  • Deterministic decisions, LLM judgment. Everything the agents decide structurally (match vs create vs conflict, health findings, index entries) is pure Python with zero LLM calls; the model only adds judgment (extraction, semantics, wording) and writes.
  • Human-in-the-loop where it hurts. Page deletion pauses for human approval wherever it is possible; contradiction flags pause for approve / edit / reject in ingest. The CLI and the Streamlit UI both drive the same Command(resume=…) flow.
  • Three-level eval suite. 206 tests in tests/levels/ — mechanical rules, agent behavior, and answer quality — run on a neutral corpus, with real-LLM tests that skip without a key.

1. Why agents instead of one pipeline?

Each operation — ingest, query, lint, fix — is a different kind of work with different permissions, different budgets, and different outputs. One "god-agent" holding every tool would need the union of all permissions to exist, which is the worst security posture for an LLM. Instead, each agent is assembled with a tool list that is the minimum required for its job:

Agent Job Tools Writes? HITL
ingest Read a source, extract structured knowledge, create / update / flag pages 12 (read + match + write) Yes — pages, index, log delete + contradiction (approve / edit / reject)
query Answer questions from the wiki with grounded citations 3 (read-only) No None
lint Structural audit + semantic review → lint report 4 (audit + read + report) Only the report file None in practice (read-only tools)
fix Resolve lint issues with pinned kind→tool fixes 7 (read + fix + index) Yes — pages, index delete (approve / reject)

Beneath all four sits the deterministic wiki engine — pure Python, zero LLM calls — documented separately in wiki-engine.html →. This page is about the LLM layer: how agents are built, prompted, constrained, and looped.

2. The agent factory

Every agent is produced by one function, factory.build_agent(), which wraps LangChain's create_agent() with a fixed middleware chain and a MemorySaver checkpointer: 

def build_agent(model, tools, system_prompt, middleware=None, model_name="unknown"):
    tracker = TokenTracker(model_name)
    set_tracker(tracker)

    # Always-on middleware, in order: audit → path guard → token capture
    all_middleware = [
        audit_logging_middleware,
        path_guard_middleware,
        token_capture_middleware,
    ] + (middleware or [])   # agent-specific HITL goes last

    agent = create_agent(
        model=model, tools=tools, system_prompt=system_prompt,
        middleware=all_middleware,
        checkpointer=MemorySaver(),
    )
    agent._token_tracker = tracker
    return agent
  • Model — ChatOpenAI built with an explicit base_url/api_key and temperature=0, so any OpenAI-compatible provider (Azure, OpenRouter, local proxy) works via env vars.
  • Checkpointer — a fresh MemorySaver per agent, with a per-invocation thread_id from the CLI. State never leaks between runs.
  • Recursion limits — query/lint/fix run at the default (30 via config for query; LangGraph's built-in cap otherwise); ingest gets 200 because a single ingest can legitimately span many create/update super-steps.
  • Token tracker — attached as agent._token_tracker so the CLI can log usage summaries; the frontend mirrors the pattern for the query agent's _nav_capture.

3. The agent loop & middleware pipeline

The loop is the standard LangGraph cycle — model call → tool call → observe → repeat — with middleware interposed at two points: wrap_tool_call around every tool execution, and the @after_model hook after every LLM call. Both sync (invoke()/stream() in the CLI) and async (astream() in the Streamlit UI) hooks are implemented, so one middleware set serves every entry point.

  • audit_logging_middleware — records every tool call (name, args, result, duration) to the audit log; failures are logged with the exception and elapsed time.
  • path_guard_middleware — the write-tools set (create_page, update_page, delete_wiki_page, write_lint_report, add_frontmatter, fix_link, append_related_section) must not receive arguments containing raw/, starting with /, or containing ... read_source is exempt — it legitimately reads raw sources. New write tools must join the set or they are unguarded by design.
  • token_capture_middleware — an @after_model hook that extracts token_usage (or usage) from the last message's response_metadata and records it on the session tracker.
  • HumanInTheLoopMiddleware — agent-specific (see §7): pauses on delete_wiki_page for all agents and on flag_contradiction for ingest, with explicit decision sets.

4. System prompt assembly

Four builders in agents/prompts.py assemble the system prompts. They all follow the same skeleton — role, schema, inventory, workflow, rules: 

def build_query_prompt(agents_md: str, wiki_index: str = "") -> str:
    index_section = f"\n# Current Wiki Pages\n{wiki_index}\n" if wiki_index else ""
    return f"""You are the Query Agent for a persistent LLM wiki.

# Wiki Schema
{agents_md}{index_section}

# Workflow
1. Call `wiki_search` — one call retrieves ranked relevant pages ...
2. Call `wiki_read_page` for the few pages you will cite ...
3. Write your final answer as a plain message with inline [[Page]] links.

# Grounding
- ALWAYS cite every page you read ... citations for any other page are dropped automatically.
# Rules
- Read-only. Do not call any write tool (none provided).
- Never infer or hallucinate content from page names alone."""

Four ingredients, in order:

  • Role — one paragraph defining the agent's job and identity.
  • AGENTS.md schema — loaded by load_agents_md (with a built-in default fallback) and injected verbatim. This is the shared contract: page types, slug naming, [[links]], frontmatter, update rules, hard rules.
  • Current wiki pages — the raw index.md injected as # Current Wiki Pages (get_index_summary). The model knows the page inventory before making a single tool call — no blind guessing of slugs.
  • Workflow + hard rules — agent-specific instructions, including the structural invariants the code enforces (see below).

Per-agent prompt highlights

Agent Prompt invariants that shape behavior
ingest Two modes (file path vs natural language). submit_extraction MUST run before any page write; match_page_tool called once per name; branch on its decision; after flag_contradiction returns, the human decision is already known — continue, never ask again. NEVER call update_index — the index is derived; end with regenerate_index + append_log.
query Cite every page read with inline [[slug]]; any other citation is dropped automatically (cite-or-die). Read-only — no write tools exist. Say so clearly when the wiki doesn't cover the question.
lint Run run_health_check FIRST as ground truth; get the full picture with wiki_scan + wiki_link_graph instead of reading pages; hard budget of ≤3 wiki_read_page calls; ALWAYS write the report, even with zero findings; never modify content pages.
fix Pinned issue-kind → tool map (missing-frontmatter → add_frontmatter, …); natural-language requests take priority over the issue list; never read lint-report-* pages; verify each fix by re-reading; end with regenerate_index when titles/content changed.

5. The four agents

5.1 Ingest Agent — compile once

Reads a source, extracts structured knowledge in one pure pass, then decides — deterministically — whether each name becomes a new page, an update, or a contradiction flag.

Tools

read_source submit_extraction match_page_tool wiki_read_page wiki_scan wiki_link_graph create_page update_page flag_contradiction regenerate_index append_log delete_wiki_page

The deliberate split: submit_extraction (tools/extraction.py) performs no writes — it validates an ExtractionResult of entities, concepts, and contradictions and returns it as JSON. It forces a structured, testable extraction boundary before any page write, and the agent never calls an "update index" tool — the index is rebuilt by regenerate_index as a derived view.

5.2 Query Agent — cite or die

Read-only. Searches with BM25, navigates pages, and writes a plain-message answer with inline [[Page]] links. There is no finalization tool: the answer is auto-built from the model's own final message by build_final_answer, which extracts every inline link as a citation and drops any whose slug was never actually navigated this turn.

Tools

wiki_search wiki_read_page wiki_summary

  • Fresh capture per invocation — agent._nav_capture = new_nav_capture() at build time, mirrored by the frontend's chat driver per turn. Every cited slug must be a page navigated this turn.
  • Confidence is inferred, not claimed: high when navigated pages are cited, medium when pages were navigated but none are cited, low when nothing was navigated.
  • Rendering — render_answer_text strips [[…]] markup for display; citations carry slug + title (from frontmatter) + section.

5.3 Lint Agent — deterministic audit + semantic judgment

The structural audit is a 0-LLM health_check; the agent adds the one thing that needs a model (duplicate coverage and cross-page consistency) and writes the report.

Tools

run_health_check wiki_link_graph wiki_read_page write_lint_report

Note the asymmetry: the agent is read-only except for write_lint_report (its tool list contains no page-write tool at all), and lint-report-* pages are excluded from the health check itself — a report can't flag itself.

5.4 Fix Agent — structured issues in, pinned fixes out

The CLI runs health_check first, converts each issue to a one-line message ([kind] slug: detail), and hands it to the Fix Agent, which applies a pinned kind→tool map. There is no shell tool in this agent — it can only act through the wiki tools.

Tools

wiki_read_page edit_wiki_page add_frontmatter fix_link append_related_section regenerate_index delete_wiki_page

7. Human-in-the-loop

HumanInTheLoopMiddleware (from langchain.agents.middleware) interrupts the agent run before a dangerous tool executes. The configuration is explicit and per-agent:

Agent Interrupts on Allowed decisions
ingest delete_wiki_page, flag_contradiction approve / reject; contradiction adds edit
query — (no middleware) —
lint delete_wiki_page (declared; tool not in its list) approve / reject
fix delete_wiki_page approve / reject

How the decision flows back

On interruption, the run result carries __interrupt__ with the pending action_requests. The caller resumes with a LangGraph Command: 

result = agent.invoke(Command(resume={
    "decisions": [{"type": "approve"}]
}), config=config)
  • CLI — agentic-rag ingest prompts [a]pprove all / [e]dit one / [r]eject all; lint and fix prompt approve/reject. An edit decision rewrites proposed_resolution in the flagged action and resumes.
  • Frontend — frontend/agent_driver.py:build_decisions builds the same resume payload from the UI's approve/edit/reject controls.
  • In-agent semantics — the ingest prompt tells the agent that once flag_contradiction returns, the human decision is already known: approve → proceed with the proposed resolution; reject → leave the page unchanged; edit → apply the edited resolution. The agent must not re-ask.

8. CLI reference

Single entry point: the agentic-rag script (typer). Each command builds its agent fresh and runs it with a unique thread_id.

Command Arguments What it does
ingest <path-or-text> File path → file mode; anything else → natural-language mode. Runs the ingest agent with HITL (a/e/r) until all interrupts resolve.
query <question> Runs the query agent; renders via build_final_answer + render_answer_text → Answer / Confidence / Citations.
lint — Runs the lint agent; the deterministic health check is the ground truth, the model adds semantics and writes the report.
fix [kind | slug | "latest"] Runs health_check locally, filters to the argument (or latest = all), passes one-line issues to the fix agent; unknown filters pass the raw request through as a natural-language instruction with issues as context.
status — Wiki page count, index entry count, last log entry — all deterministic, no agent.
log [--tail N] Tail parsed log entries (no agent).

9. Frontend (Streamlit)

The web UI (frontend/app.py) is not a separate implementation — it drives the same four agents in-process (frontend/builders.py calls build_query_agent, build_ingest_agent, …) and streams them with agent.astream(). The middleware's async hooks exist precisely so the same chain works under astream.

  • Query driver (frontend/query_driver.py) — for the query page, it creates a fresh new_nav_capture() per turn (cite-or-die), streams stream_mode="messages", and renders the final QueryAnswer with the same build_final_answer the CLI uses.
  • Tool chips — tool calls surface live in the UI, so the loop is visible: search → read → answer.
  • HITL controls — agent_driver.build_decisions turns the UI's approve/edit/reject buttons into the same Command(resume=…) payloads.
  • Run it — uv sync --extra ui then uv run streamlit run frontend/app.py.

10. Agent Evaluation Architecture

The evaluation suite in tests/levels/ adopts a three-tier testing pyramid designed to decouple deterministic system guarantees from probabilistic model behavior. By separating code-level integrity, tool-trajectory discipline, and semantic output quality, the suite ensures robust agent orchestration while minimizing API token overhead.

Level 1 — Deterministic Quality Gates & Corpus Integrity (0-LLM)

Fast, offline CI/CD checks executed with zero LLM API calls. Level 1 validates structural invariants, security boundaries, and data integrity across the wiki corpus:

  • Schema Conformance: Asserts that every markdown page strictly adheres to the AGENTS.md specification, validating YAML frontmatter fields, directory placement, and required ## Related sections.
  • Path-Guard Safety Matrix: Exhaustively tests the PathGuardMiddleware against a 7 write-tool × 5 attack vector matrix (traversal attacks, raw/ protection, absolute paths).
  • Link Integrity & Graph Topology: Verifies full graph resolution for Obsidian-style [[links]] and guarantees zero orphan pages across the corpus.
  • Cite-or-Die Grounding (NavCapture): Validates that any final response referencing unnavigated page slugs has those citations deterministically stripped before rendering.

Level 2 — Trajectory Contracts & Orchestrator Discipline

Evaluates agent tool-calling mechanics, middleware interlocks, and state consistency across two distinct layers:

  • Deterministic Engine & Pipeline Layer (Scripted 0-LLM): Uses a ScriptedChatModel to verify that the LangChain/LangGraph orchestrator correctly enforces per-role tool whitelists, turn-efficiency caps (query ≤ 5, lint ≤ 4, fix ≤ 8, ingest ≤ 15), headless HITL interrupt/resume contracts (via eval_hitl.py), and post-execution disk state consistency (idempotent index regeneration and log appending).
  • Real-LLM Acceptance Tier (Causal DAG Contracts): Evaluates live model reasoning against declarative Directed Acyclic Graph (DAG) contracts. Rather than asserting brittle fixed tool sequences, it validates causal prerequisites (e.g., wiki_search before wiki_read_page), forbidden tools per role, and terminal invariants. Requires a ≥ 80% aggregate pass rate across pinned tasks.

Level 3 — RAG Performance & Semantic Quality (LLM-as-a-Judge)

Measures retrieval effectiveness and output trustworthiness:

  • Context Recall @ K: Evaluates BM25 retrieval and 1-hop link expansion accuracy against curated query-slug benchmarks on a neutral eval corpus.
  • Calibrated LLM Judges: Uses zero-temperature, few-shot anchored judge prompts (scoring 1.0, 0.5, 0.0) with strict Pydantic JSON parsing to measure Faithfulness (grounding against navigated context) and Answer Relevancy without score drift.
  • Contradiction Resolution: Validates end-to-end handling when new ingests conflict with existing wiki claims, ensuring proper flagging and HITL intervention.

Harness & Execution Strategy

To maintain absolute isolation, all tests operate on temporary copies of clean (eval_wiki), raw (eval_raw), or defective (eval_broken_wiki) fixture trees via copy_eval_wiki(tmp_path). The committed source fixtures are immutable and self-checked via content hashes. All Human-In-The-Loop (HITL) interrupts are resumed programmatically via resume_auto(), preventing blocking CLI input() calls during headless CI/CD execution.

Running the Evaluation Suite

# Run full evaluation suite (real-LLM tests auto-skip if OPENAI_API_KEY is unset)
uv run pytest tests/levels/ -q

# Run per-level target suites
uv run pytest tests/levels/level1 -q   # Level 1: Deterministic Quality Gates (0-LLM)
uv run pytest tests/levels/level2 -q   # Level 2: Trajectory Contracts & Tool Calling
uv run pytest tests/levels/level3 -q   # Level 3: RAG Metrics & LLM-as-a-Judge

11. Glossary

Term Meaning
Agent A compiled LangGraph runnable from create_agent(): model + scoped tools + system prompt + middleware + MemorySaver checkpointer. Four exist: ingest, query, lint, fix.
Middleware Hooks around tool calls (wrap_tool_call) and after model calls (@after_model). Always-on: audit logging, path guard, token capture. Agent-specific: HITL.
HITL Human-in-the-loop: a middleware interrupt that pauses the agent until a human approves / rejects / edits (mandatory for page deletion, and for contradiction flags in ingest).
NavCapture The per-invocation store of slugs the agent actually navigated (populated by wiki_search / wiki_read_page). The cite-or-die gate validates citations against it.
Cite-or-die The query-agent rule: an answer may only cite pages whose slugs were actually navigated this turn — enforced automatically because answers are built from the model output, not a submit tool.
submit_extraction The ingest agent's pure finalization-as-tool: forces structured Entity/Concept/Contradiction JSON before any page write. No writes, never raises.
match_page Deterministic decision for a name: exact / similar → update, none → create, conflict → flag. No score thresholds.
regenerate_index The only "index" operation — rebuilds index.md from the pages as a derived view. The ingest prompt forbids calling an update_index tool.
Path guard Middleware that rejects raw/, absolute, and .. paths on write tools; read_source is the only exempt tool.
Token capture @after_model hook that records token_usage from each LLM response onto the run's TokenTracker.
Recursion limit Maximum agent loop turns per invocation: 30 for query, 200 for ingest (which legitimately spans many create/update super-steps).
Scripted fake model A test fixture that replays a predetermined tool-call script instead of calling an LLM — how agent integration tests run offline.
Level 1 / 2 / 3 evals The three-tier test suite in tests/levels/: mechanical rules (L1), agent tool behavior (L2), and answer quality (L3).
Neutral eval corpus A small fake wiki shipped with the repo for tests to work on — each test copies it to a temp folder and never changes the original.
TrajectoryContract A rule sheet describing how an agent may use its tools — which ones, in what order, and how many calls are allowed.
