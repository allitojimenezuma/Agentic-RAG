1. The 60-Second Pitch

Say this out loud, slowly:

I built a system called Agentic RAG. It is a document system with AI agents.

Normal RAG searches the documents every time you ask a question.
My system is different: the AI reads the documents once and builds
a wiki — pages for people, concepts, and ideas, all linked together.

When you ask a question, the AI navigates the wiki and answers from it.
The knowledge grows over time and never needs re-searching.

The system has four agents: one reads documents, one answers questions,
one checks the health of the wiki, and one fixes problems. Humans approve
dangerous actions like deleting pages. And I test the quality of the answers
with AI judges — for example, checking that the AI does not invent facts.

Why this works: it shows you understand (1) the problem, (2) your solution, (3) the parts, (4) safety, and (5) testing.

2. The Big Ideas

Know these concepts. For each one, you can say the one-sentence version.

IdeaSimple explanationOne sentence you can say
Agent An AI that thinks in a loop: it decides, calls a tool, sees the result, decides again, until it has an answer. "An agent is an AI with tools and a loop."
Human-in-the-loop (HITL) The agent pauses and asks a human before doing something risky, like deleting a page. "The agent asks for approval before dangerous actions."
Grounding (cite-or-die) The agent can only mention pages it actually read during the answer. Links it never visited are dropped. "If the agent did not read it, it cannot cite it."
LLM-as-judge Another AI scores the answers: faithful (no lies) and relevant (answers the question). "I evaluate answers with AI judges, not by feeling."
Evaluation pyramid Three test levels: cheap tests with no AI, tests with fake models, and real AI tests. "Cheap checks first, expensive AI checks last."
Spec-driven workflow First write a plan, then execute small tasks one by one. "Plan first, execute in small steps."

3. Your Workflow: Planner + Orchestrator

You build features with sub-agents in two steps. It saves tokens and keeps agents focused on their job.

Step 1 — Planner (one session)

  • Reads the request and the code.
  • Writes docs/spec.md — what to do, what NOT to do, exact file names, test command.
  • Writes docs/progress.md — the task list (T1, T2, T3...).

Step 2 — Orchestrator (a new session)

  • Takes one task at a time.
  • Sends it to a cheap executor agent (small model, small job).
  • Runs the tests itself (free, no AI needed).
  • Checks scope with git diff — if the executor changed more files than allowed, it failed (this is free too).
  • Uses the expensive model only when really stuck.

Why it works: the plan pins every decision, so the executor cannot "do more than asked" — the same problem you had with DeepSeek.

4. Pitch Tips

Tip 1 — Have 3 stories ready

Interviewers love real examples. Memorize these three:

grounding "I made a rule: the agent can only cite pages it really read. If the answer has a link to a page it never visited, the system drops it. This stops fake citations."

safety "Deleting a page always needs human approval. The agent pauses, I approve or reject, and it continues. In tests, I automate the approval so CI never blocks."

testing "I have three test levels. Level 1 is free and offline. Level 2 uses scripted fake models. Level 3 uses AI judges to score faithfulness and relevancy. The real-AI tests skip automatically if there is no API key."

Tip 2 — Be ready for these questions

QuestionGood answer
Why agents instead of one pipeline? "A pipeline has fixed steps. An agent decides the steps itself. My system does not know in advance which wiki pages are needed, so an agent is better."
How do you test an AI agent? "In layers: deterministic checks with no AI, scripted model tests, and AI judges for answer quality. Tests that need a real AI skip when there is no API key, so CI always works."
How do you stop the AI from inventing facts? "Two ways: grounding — it can only cite what it read — and faithfulness evaluation — an AI judge checks that every claim in the answer is in the context."
What would you improve? "More retrieval options like hybrid search, better chunking, and evaluating with more judge metrics."

Tip 3 — Talk about your skills

You made reference skills for LangChain, HITL, and DeepEval. Say: "I built reference skills for the libraries I use, so any AI agent I work with follows the current API instead of guessing." This shows you think about AI workflows, not just code.

5. Recommendations

  1. Practice the pitch out loud — 3 times. Time it. It should be under 60 seconds.
  2. Know the three skills — read langchain-agents, langchain-hitl-middleware, and deepeval-agent-testing the night before.
  3. Do not guess APIs in the interview — if you do not remember an API, say: "I would check the docs / my skill before writing it." That is a good answer. It shows you do not hallucinate — the same rule your agents follow.
  4. Speak in examples — instead of theory, tell what you did: "In my project, I..."
  5. Keep answers short — 3 to 5 sentences, then stop. If they want more, they will ask.
  6. If you do not know something — say "I do not know yet, but this is how I would learn it." Never invent facts.

Good luck. You built something real. Just tell them how it works, simply.
