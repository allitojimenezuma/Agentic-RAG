Agentic RAG — A Wiki That Compounds

An agentic RAG system that maintains a persistent, interlinked Markdown wiki as a compounding artifact. Agents compile each source once into entities, concepts, cross-references, and flagged contradictions — so every later query navigates a curated knowledge base instead of re-deriving answers from raw chunks.

1. Why not classic RAG?

Classic RAG stores raw documents as chunks in a vector store. Every query pays the same price: embed the question, retrieve the same chunks, and ask the model to re-synthesize an answer from context. Nothing is learned between queries, cross-document contradictions resurface constantly, and there is no notion of "knowledge that has already been processed."

This project takes the opposite stance: the wiki is the artifact. A source is ingested once into structured pages, links, and contradiction flags; queries then read a small, curated, interlinked graph. Synthesis is still per-query, but retrieval and understanding are not.

DimensionChunk-based RAGWiki-based (this project)
Cost per queryFull retrieval + synthesis over raw chunks, every timeSmall BM25 search over curated pages + navigation
Cross-document synthesisRe-derived from scattered chunks each queryCompiled once into pages and [[links]]
ContradictionsBoth claims surface again and againDetected at ingest, flagged for human resolution
Knowledge over timeFlat — a new source adds more chunks, not more understandingCompounds — pages update, links grow, index is a derived view
Source latencyQueryable immediately, shallowlyIngest is deeper, but the wiki answers better afterward
Failure modeHallucinated citations from irrelevant chunksCite-or-die grounding gate drops any unvisited citation

2. Architecture overview

Four LangChain agents (ingest, query, lint, fix) sit between two worlds: an immutable raw/ directory of source documents and an LLM-owned wiki/. A schema file (AGENTS.md) is injected into every system prompt so all agents share one set of page conventions.

A typer CLI (agentic-rag) is the only human entry point: it runs one agent per command, prints results, and wires HITL approvals.

3. The three layers

The whole design reduces to one ownership rule per layer:

LayerOwnerRulesPersistence
raw/Immutable Agents read sources, never write. The path guard blocks raw/ paths on every write tool; read_source is the only exempt tool. Committed
wiki/LLM-owned Pages (entities/, concepts/, sources/, …) plus index.md and log.md. index.md is a derived view — rebuilt atomically from the model, never hand-edited. Runtime data, gitignored
AGENTS.mdSchema / conventions Page types, slug naming, [[links]], frontmatter fields, update rules. Loaded and injected into every agent system prompt. Committed

Wiki schema highlights (AGENTS.md)

  • Page types: entity, concept, source, comparison, overview.
  • Naming: lowercase slugs, hyphens for spaces — entities/mlx.md, concepts/3d-gaussian-splatting.md.
  • Links: Obsidian-style [[Page Name]]; every page ends with a ## Related section.
  • Frontmatter: YAML with slug, type, title, sources, updated, tags.
  • Update rules: new info supersedes old; contradictions are flagged (never silently overwritten); index + log updated on every write.

4. The agent loop & middleware pipeline

Every agent is built by factory.build_agent() around LangChain create_agent(). The system prompt = role instructions + the full AGENTS.md schema. The loop is the standard model → tool-call → observe → repeat cycle, with a MemorySaver checkpointer for per-invocation state and a recursion limit of 30.

  • audit_logging_middleware — records every tool call to the audit trail.
  • path_guard_middleware — rejects raw/, absolute, and .. paths on all write tools.
  • token_capture_middleware — tracks token usage per run.
  • HumanInTheLoopMiddleware — pauses on delete_wiki_page (all agents) and flag_contradiction (ingest) with explicit decision sets.

5. The four agents

5.1 Ingest Agent — compile once

Reads a source, extracts structured knowledge, and decides — deterministically — whether each name becomes a new page, an update, or a contradiction flag.

Tools

read_source submit_extraction match_page_tool wiki_read_page create_page update_page flag_contradiction regenerate_index append_log delete_wiki_page

Note the deliberate split: submit_extraction performs no writes, and the agent never calls an “update index” tool — the index is rebuilt by regenerate_index as a derived view.

5.2 Query Agent — cite or die

Read-only. Searches with BM25, navigates pages, and must submit a grounded answer whose citations were all actually visited.

Tools

wiki_search wiki_read_page wiki_summary submit_query_answer

5.3 Lint Agent — deterministic audit + semantic judgment

The structural audit is a 0-LLM health_check; the agent adds the one thing that needs a model (duplicate coverage) and writes the report.

Tools

run_health_check wiki_link_graph wiki_read_page write_lint_report

lint-report-* pages are excluded from the audit itself.

5.4 Fix Agent — structured issues in, pinned fixes out

The CLI runs health_check, converts each issue to a one-line message ([kind] slug: detail), and hands it to the Fix Agent, which applies a pinned kind→tool map. There is no shell tool in this agent.

Tools

wiki_read_page edit_wiki_page add_frontmatter fix_link append_related_section regenerate_index delete_wiki_page

6. The deterministic wiki engine

Everything below the agents is pure Python — zero LLM calls. This is what keeps the system testable, cheap, and honest.

6.1 Wiki model (wiki/model.py)

load_wiki(path) parses the wiki directory into a Wiki(pages, by_slug). Each Page exposes slug, rel_path, parsed frontmatter, sections, outbound [[links]], and word count. Pages missing frontmatter get a synthesized one so downstream tools never crash on malformed input.

6.2 BM25 search + link expansion (wiki/search.py)

search(query, k=8, types, tags, expand_links=True, depth=1) ranks pages by BM25, then optionally expands one hop of [[links]]; expand-link hits are scored at 0.1 so direct hits always outrank them.

6.3 match_page decision tree (wiki/match.py)

The heart of ingest: decide before any write whether a name should update an existing page, create a new one, or be flagged as a contradiction. Pure logic, no thresholds.

6.4 The derived index (wiki/dedupe_index.py)

index.md is not a source of truth — it is rebuilt atomically by regenerate_index from the parsed wiki model. No agent ever hand-edits it, so it cannot drift from reality.

7. Safety & guardrails

MechanismWhereWhat it prevents
Path guard middleware/guardrails.py Write tools reject any argument containing raw/, starting with /, or containing ... read_source is exempt (it legitimately reads raw sources). New write tools must be added to the write_tools set.
HITL HumanInTheLoopMiddleware delete_wiki_page always pauses for approve/reject (all four agents); flag_contradiction adds approve/edit/reject (ingest).
Cite-or-die grounding tools/grounding.py (NavCapture) validate_citations drops any citation whose slug the agent never navigated — fabricated references cannot reach the user.
Atomic writes io/wiki_io.py, dedupe_index.py Temp-file + rename on every wiki write and index rebuild — no torn files on crash.
No shell in Fix agents/fix.py The execute-command tool was removed — the fix agent can only act through the wiki tools.

10. Quickstart

# 1. Install
uv venv
source .venv/bin/activate
uv pip install -e ".[dev]"

# 2. Configure
cp .env.example .env          # set OPENAI_API_KEY (and OPENAI_BASE_URL if needed)

# 3. Ingest a source (pdf, docx, md, html, ...)
agentic-rag ingest raw/sample.md

# 4. Ask questions against the wiki
agentic-rag query "What is MLX?"

# 5. Audit health, then fix what the health check found
agentic-rag lint
agentic-rag fix latest

# 6. Inspect state
agentic-rag status
agentic-rag log --tail 5

11. Glossary

TermMeaning
Compounding artifactThe wiki gets better with every ingest: pages update, links grow, contradictions are resolved — knowledge accumulates instead of being re-derived per query.
FrontmatterYAML header on each page (slug, type, title, sources, updated, tags). Pages missing it get a synthesized one at load time.
OrphanA page with no inbound [[links]] from other pages or the index — lint kind, severity high.
HITLHuman-in-the-loop: a middleware interrupt that pauses the agent until a human approves/rejects/edits (mandatory for page deletion and contradiction flags).
NavCaptureThe grounding mechanism that records which page slugs the agent actually visited; validate_citations drops any citation not in that set.
matched_viaSearch-result metadata distinguishing direct hits from expand-link hits; the matcher only counts direct hits when deciding similar vs conflict.

SeverityPer-kind lint weight: missing-frontmatter = critical; orphan/missing-index/broken-link/empty = high; missing-related/stale = medium.
Cite-or-dieThe query-agent rule: an answer may only cite pages whose slugs were actually navigated.
